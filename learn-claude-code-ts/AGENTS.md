# TypeScript 学习约定

## 范围与目标

- 本目录用于对照仓库中的 Python 教程，逐章学习并实现 TypeScript 版本。
- 所有新增学习材料都放在 `learn-claude-code-ts/` 内，包括原理讲解、源码分析、问答结论、TS 代码、实验、排错记录与复盘。
- 仓库根目录的 Python 课程作为参考；除非用户明确要求，不修改原版文件。
- 默认用中文记录，保留必要的英文术语与代码标识符。

## 目录规则

- 沿用原版 `s01_agent_loop` 至 `s17_goal_loop` 的编号、名称和学习顺序，不另建一套平行章节体系。
- 每章 `README.md` 是该章学习入口；TS 实现从本章 `code.ts` 开始，代码复杂时再按需拆分。
- 原版有多语言文档时，按原文件名完整迁移：`README.md` 为英文、`README.zh.md` 为中文、`README.ja.md` 为日文；学习索引优先链接中文，各语言的正文、代码示例和运行命令都应对应 TS 实现。
- 原版图片按原目录与文件名原样复制，不以新画的图替代。图片中保留的 Python 命名在正文解释其 TS 对应关系。
- 原版源码头部的章节说明、ASCII 流程图和关键结论也是学习内容，迁移到对应 `code.ts` 的头部块注释中；图内文件名、函数名应对应 TS 实现。
- 完成章节迁移前，对照原版核对 Markdown、图片和源码头部说明，检查图片字节一致性和文档链接，不能只迁移中文正文或代码。
- 章节专属示例、图示和实验材料留在本章目录。跨章节材料按需放在本目录的 `docs/` 中，并从相关章节链接。
- 工程配置和依赖留在本目录，首次实现时再按实际需要添加，不提前创建空代码或引入框架。

## 学习与记录方式

- 先读取对应 Python 章节的文档与代码，再解释原理或编写 TS 实现；学习顺序不代表每章完整继承上一章代码。
- 迁移以对照原版学习为目的，逐文件保持章节独立性、内容范围、主要功能和执行流程。具体实现遵循 TypeScript 习惯：允许 camelCase、原生条件判断和合理的细小运行时差异，不要求逐行照搬 Python。
- 不得改变各文件的职责或擅自新增能力；原版独立的章节不抽成跨章公共父类、共享 Agent Loop、通用 CLI 或工厂。章节内部可以用清晰、惯用的 TS 写法简化实现；不为模拟 Python 的真值等语言细节新增通用兼容层。
- 按用户当前学习进度推进，不在未经要求时一次性代写后续课程。
- 每次形成有价值的讲解、问答结论、实现或排错结果，都更新对应章节，不能只留在聊天里。
- 记录应覆盖：核心原理、Python 源码导读、TypeScript 实现、实验与验证、问题与复盘。未学习的部分明确标记待补充，不伪造完成状态。
- Python 到 TS 无法直接对应的标准库或运行时差异必须明确记录，不用“概念上对应”替代源码结构与行为对齐。
- 记录验证命令、执行目录、预期结果、实际结果与限制。没有执行的验证必须注明“未执行”。
- 章节有进展时同步更新本目录总 `README.md` 的状态和下一步。
- 不把密钥、令牌或其他敏感数据写入学习笔记、示例或日志。
